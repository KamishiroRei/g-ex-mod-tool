# G-EX 脚本与条目制作

`toolRoot` 为包含本技能的 `modtool/`，`gameRoot` 通常是其父目录；独立下载时使用用户选定且包含 `ExtentData/Parts` 的游戏目录。所有路径相对此二者解析，不依赖开发者电脑的绝对目录、账号或连接器。

## 选择实际所有者

| 修改目标 | 正式入口 | 生效方式 |
|---|---|---|
| 条目归属、名称/说明覆盖、资源/驱动陈列与属性显示 | `gameRoot/UI/Hangar/inspector.json` | 游戏现役显示链读取；工具响应文件变化 |
| 部件/驱动真实名称、说明与玩法定义 | `gameRoot/ExtentData/Parts/**/*.json` | 按定义与准备阶段的真实刷新边界更新 |
| 格纳库界面布局/交互/动效 | `gameRoot/UI/Hangar/*.lua` | 现役 Lua 热重载；保留未修改的设计 |
| 驱动行为脚本 | 正式定义中实际引用的 `gameRoot/Mods/` 下 Lua | 沿该脚本的实际消费者，不另造平行行为定义 |
| 工具取值、投影与界面 | `toolRoot/gex_mod_tool/` | 配置/外置 QSS 按事件刷新；Python 程序修改走正式构建 |

先读将修改的实际定义、调用者和 [展示 Schema](../../../schema/inspector.schema.json)。需要字段格式、层级、取值与生效边界时，读取 [脚本合同](references/script-contracts.md)。不要依据名称猜资源关系或编造属性值。

## 直接相关的设计规则

- 部件内统一陈列条目，公开驱动归于所属条目；单个同名驱动也显示。核心/操作系统表达其产品身份，不用“UI”作为类型，不把同一操作系统的界面与操作拆成两个展示项。
- 列表只保留识别、选择、操作所需内容，不加驱动简约描述。详情先展示威力、冲击力、射程/范围等攻击属性，再用细分隔区分弹药、装填等常规属性。
- 觉醒倍率、发射方式、每次耗弹等内部实现细节不进入默认玩家展示。描述以实际动作、方向与效果为主，简短自然，不穷举全部机制。
- 属性值来自真实规则/资源。手填 `value` 仅覆盖显示，不改玩法值。修改真正伤害或资源数值时，查其正式定义与规则所有者。
- 自动条目来自真实资源与公开驱动。删除显式覆盖可能恢复自动条目，不意味着删除了真实资源或驱动；当前合同没有隐藏整个自动条目的字段。
- 未涉及的字段、顺序、归属、数量和功能继续保留；未知 JSON 字段不得因工具不认识而丢弃。

## 工具与游戏同步维护

工程接口或脚本合同变化时，修改实际责任层，并同步受影响的 `catalog.py`、`model.py`、Schema、本技能及构建收集项。保留稳定 DefinitionId、CostTag 和条目 id；不按显示文本重建身份。参考基准图 [approved-ui.png](../../../design/approved-ui.png) 维护已采用的层级和外观，示例图不裁定实际部件数量或玩法数值。

工具使用文件事件刷新实际读取的配置、定义和外置样式，刷新不得静默丢弃未保存编辑。游戏内容热重载服务战斗外制作与准备阶段；战斗按进入时的准备快照运行。涉及原生接口或二进制能力变化时，按对应源码版本构建，不声称所有 C++ 改动都可由保存脚本即时生效。

交付说明写清实际修改与使用入口，遵守用户指定的构建和观察边界；不因本技能自动增加启动游戏、测试或发布权限。
